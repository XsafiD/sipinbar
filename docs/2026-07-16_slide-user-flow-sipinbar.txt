## Executive Summary

**Apa itu SIPINBAR?**

- Sistem manajemen inventaris desa yang digitalisasi proses manual peminjaman barang
- Mengelola peminjaman: proyektor, kursi, tenda, sound system, peralatan masak, dll.

**Masalah yang Diselesaikan:**

| Masalah | Solusi |
|---------|--------|
| Pencatatan manual berbasis buku | Digitalisasi pencatatan |
| Double-booking | Validasi ketersediaan real-time |
| Sulit tracking pengembalian terlambat | Perhitungan denda otomatis |
| Tidak ada riwayat historis | Laporan statistik lengkap |

## Guest Flow 1: Self-Service Registration

**Flow Diagram**

```
Guest → Visit Landing → Click "Daftar" → Fill Form →
      Submit → Registration Success → Status: "menunggu" →
      Wait Admin Verification → (if approved) → Ready to Borrow
```

**Form Fields**

- NIK (16 digit, required, unique)
- Nama lengkap (required)
- Password + Konfirmasi (min 6 karakter)
- Alamat (required)
- Telepon (required, numeric)
- RT/RW (required)

**Output:** Akun created dengan status `menunggu`

## Warga Flow 1: Submit Peminjaman Barang

**Flow Diagram**

```
Warga → Dashboard → Click "Ajukan Peminjaman" → Fill Form →
      Select Barang(s) + Jumlah + Tanggal → Submit →
      Validate Availability → Create Peminjaman → Status: "diajukan"
```

**Business Rules Validated**

- **BR-01:** Only active citizens can borrow
- **BR-02:** Return date > Borrow date
- **BR-03:** Anti double-booking (overlap detection)
- **BR-04:** Stock validation
- **BR-05:** No duplicate items in single request

**Output:** Peminjaman created dengan unique kode (PIN-XXXXXX)

<!-- Slide 14: Admin Flow 3 - Mark as Borrowed -->
## Admin Flow 3: Mark as Borrowed (Serahkan Barang)

**Flow Diagram**

```
Admin → Search Approved Peminjaman → Click Detail →
      Verify Identity → Click "Serahkan Barang" →
      Update Status → Reduce Stock
```

**Physical Verification**

- [ ] Verifikasi identitas warga (NIK, nama)
- [ ] Cek fisik barang (kondisi, kelengkapan)
- [ ] Fungsi normal (untuk elektronik)

**System Actions**

```
status: 'disetujui' → 'dipinjam'
tanggal_pinjam = TODAY()
barang.jumlah_unit -= detail.jumlah (for each item)
```

**Output:** Stok berkurang real-time, warga menerima notifikasi

<!-- Slide 15: Admin Flow 4 - Process Return -->
## Admin Flow 4: Process Return (Pengembalian)

**Flow Diagram**

```
Admin → Search Borrowed Peminjaman → Click Detail →
      Verify Return Items → Check Condition →
      Input Actual Return Date → Calculate Denda →
      Process → Restore Stock
```

**Fine Calculation Logic**

```python
hari_terlambat = MAX(0, tanggal_aktual - tanggal_harus_kembali)
denda_per_barang = tarif_denda_per_hari * hari_terlambat * jumlah
denda_total = SUM(denda_per_barang)
```

**Category Rates**

| Kategori | Tarif Denda |
|----------|-------------|
| Elektronik | Rp 5.000/hari |
| Furniture | Rp 2.000/hari |
| Peralatan | Rp 3.000/hari |

---

<!-- Slide 16: Fine Calculation Example -->
## Fine Calculation Example

**Scenario:**

- Warga meminjam 2 Proyektor (Elektronik)
- Durasi: 3 hari
- Harus kembali: 2026-07-10
- Aktual kembali: 2026-07-13 (terlambat 3 hari)

**Calculation:**

```
hari_terlambat = 2026-07-13 - 2026-07-10 = 3 hari
tarif_elektronik = Rp 5.000/hari
denda_per_barang = 3 hari × Rp 5.000/hari = Rp 15.000
denda_total = 2 barang × Rp 15.000 = Rp 30.000
```

**Polymorphic Implementation:**

```python
def hitung_denda(self, hari_terlambat, jumlah):
    return self.kategori.tarif_denda_per_hari * hari_terlambat * jumlah
```

## Admin Flow 5: Manage Inventory (Kelola Inventaris)

**Three Operations**

```
┌─────────────────────────────────────────────┐

- Foto upload (optional, max 2MB)
- Deskripsi (optional)

**Soft Delete:**

- Set `deleted_at = NOW()`
- Hide from catalog
- Keep in historical records

<!-- Slide 18: Admin Flow 6 - Block/Unblock Warga -->
## Admin Flow 6: Block/Unblock Citizen

**Block Flow**

```
Admin → Kelola Warga → Click Detail →
      Review Pelanggaran → Click "Blokir" →
      status: 'aktif' → 'diblokir'
```

**Blocking Use Cases:**

- Warga tidak mengembalikan barang
- Warga merusak barang
- Pelanggaran berat

**Unblock Flow**

```
Admin → Filter 'diblokir' → Click Detail →
      Click "Aktifkan" → status: 'diblokir' → 'aktif'
```

**Unblocking Use Cases:**

- Kewajiban selesai (barang kembali + denda lunas)
- Kesalahan sistem (salah blokir)

<!-- Slide 23: Error Handling -->
## Error Handling & Edge Cases

**Error Categories**

| Category | Example Error | Recovery |
|----------|---------------|----------|
| Auth | E-AUTH-001: Wrong password | Retry login |
| Registration | E-REG-001: NIK exists | Use different NIK |
| Peminjaman | E-PIN-003: Double-booking | Choose different dates |
| Inventory | E-INV-001: Empty name | Enter name |
| Reporting | E-RPT-001: Invalid date range | Fix dates |

**Edge Cases**

- **EC-001:** Concurrent requests → SERIALIZABLE isolation
- **EC-002:** Stock becomes 0 → Re-validate before approve
- **EC-006:** Duplicate cron reminders → Anti-spam check
- **EC-007:** DB connection lost → Retry with backoff

<!-- Slide 24: OOP Implementation -->
## OOP Implementation Highlights

**4 Pilar OOP dalam SIPINBAR**

| Pilar | Implementation |
|------|----------------|
| **Encapsulation** | State transitions via controlled methods (`ajukan()`, `setujui()`, `pinjam()`, `kembalikan()`) |
| **Inheritance** | Multiple inheritance with base classes (`BarangBase`, `WargaBase`, `AdminBase`) |
| **Polymorphism** | Fine calculation per category (`barang.hitung_denda()`) |
| **Abstraction** | Abstract Base Classes in `models/base.py` |

**Architecture Pattern: Model-Service-Controller**

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  MODEL   │───│ SERVICE  │───│CONTROLLER │
│ (Barang) │    │ (Logic)  │    │  (Routes) │
└──────────┘    └──────────┘    └──────────┘
